# Aesthetic OS 两天协作方案

修订日期：2026-11-07（第 3 版）。比赛的提交时间和评分标准还没有写入本文，请负责人补上。

## 1. 现在的重点

**重点是图片，3D 暂停。** 用户不知道椭圆脸长什么样，也不知道古典型和自然型长什么样，所以每个概念都要配上真实图片。

产品流程：

```
看图鉴，先看懂概念 → 拍照识别或手动答题 → 风格报告
报告顺序：风格图 → 脸型与发型图 → 妆容图 → 身材版型图 → 明星 → 博主 → 杂志案例
```

优先级：

1. **必须有：** 下表的图鉴和明星照片墙。
2. **应该有：** 拍照识别五官并预填结果、杂志案例扩充、博主补齐。
3. **时间够再做：** 饰品、三个月计划等文字模块。
4. **暂不做：** 3D 捏脸。

## 2. 图片清单

| 图鉴 | 内容 | 数量 | 负责 |
|---|---|---|---|
| 风格 | 少女、少年、优雅、古典、自然、前卫、浪漫、戏剧 | 每种至少 6 张（现有 301 张博主图可以先用） | A |
| 明星 | 8 种风格的代表明星，含私服照 | 每种至少 3 位，每位至少 2 张私服 | A |
| 脸型 | 椭圆脸、圆脸、方脸、心形脸、长脸 | 每种 1 张示意图 + 至少 3 张真实例图 | C |
| 五官与量感 | 眉形、鼻子大小、曲线或直线、大中小量感 | 每类 1 张示意图 + 至少 2 张例图 | C |
| 发型 | 齐刘海、空气刘海、八字刘海、无刘海、直发、卷发、黑发、棕发 | 每类至少 3 张 | D |
| 妆容 | 8 种风格，区分约 5 分钟和约 15 分钟 | 每种至少 2 张 | D |
| 身材 | 梨形、曲线型、H 型、倒三角、O 型 | 每类至少 3 套穿搭 | D |
| 杂志 | 8 种风格的真实案例 | 至少 40 个 | B |

每张图都要写清：属于哪一类、图片说明、来源链接、作者或署名。

## 3. 协作方式

- **GitHub 仓库是唯一的项目来源。** 任务内容以 [Issues](https://github.com/sylviadwilson33-coder/aesthetic-os-team/issues) 为准。
- **ChatGPT 共享项目放资料和指令。** 内容要写进仓库才算完成。
- **Codex 规则写在 [AGENTS.md](../AGENTS.md)。**

流程：

1. 开始前拉取最新 `main`，新建分支 `姓名/任务名`。
2. 只改自己负责的文件，一次 PR 只做一件事。
3. 自己打开网站走一遍，把截图贴到 PR。
4. 负责人检查并合并。每半天至少合并一次。

## 4. 分工

| 人员 | 任务 | Issue | 独占范围 |
|---|---|---|---|
| 负责人（你） | 合并 PR、版权决定、用户测试、提交与演示 | — | `README.md`、`AGENTS.md` |
| 队友 A | 风格图鉴、明星照片墙；和 C 一起定拍照识别标准 | #1 | `celebrity-data.js`、`visual-style.js`、`images/visual/style/` |
| 队友 B | 杂志案例库与大图案例墙 | #2 | `app.js`、新建 `case-data.js`、`杂志官网案例*` |
| 队友 C | **先搭图鉴页面**，再做脸型五官图鉴和拍照识别 | #3 | `index.html`、`visual-guide.js`、`visual-face.js`、`photo-analysis.js`、`models/`、`images/visual/face/` |

如果有人不写代码，优先安排 B 或 D。`style.css` 是共用文件：只在末尾追加，并用模块名开头（如 `.guide-*`）。要改别人的文件，先在对方的 Issue 里说一声。

## 5. 两天节奏

| 时间 | 负责人 | 队友 |
|---|---|---|
| 第一天上午 | 邀请队友，开 15 分钟会 | **C 先提交图鉴页面框架**；其他人同时开始找图 |
| 第一天下午 | 合并 PR | A、C、D 每类至少先上 1 张图，网站上能看到全部图鉴；B 拆分数据并到 20 条 |
| 第一天晚上 | 检查哪些图还缺，决定拍照识别保留到什么程度 | 全部提交当天进度 |
| 第二天上午 | 只合并已完成的内容 | 全员补足数量；C 接好拍照识别 |
| 第二天中午 | 找 3–5 位目标用户试用，看能不能看懂图 | 停止加新功能 |
| 第二天下午 | 录演示、准备提交 | 只修问题：手机端、坏图、错别字 |

**保底：** 拍照识别不稳定时，用手动答题和图鉴演示，不影响提交。

## 6. 不能碰的红线

仓库现在是**公开**的，提交的内容所有人都能下载。

- 未取得授权的图片只放本地 `private/`，不提交。优先使用写明授权的图片、自己画的示意图，以及本人同意的照片。
- 身材照片只用成年人的穿搭照；不放儿童，不放偷拍。
- 用来校准的真人照片和三维数据绝不提交。
- `_raw/`、付费资料原件、密钥、账号、Cookie 都不提交。
- 不写没有来源的明星归类和杂志信息，不用 AI 生成人物图。
- 风格、脸型和身材只用来选穿搭，不判断性格、能力或人的价值，也不评价长相好坏。
- 演示前由负责人确认：比赛是否允许使用明星和杂志图片。
