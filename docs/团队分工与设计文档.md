# Aesthetic OS 两天协作方案

修订日期：2026-11-07。比赛的提交时间和评分标准还没有写入本文，请负责人补上。

## 1. 产品流程（验收以此为准）

```
拍照或手动答题 → 用户确认结果 → 风格报告
报告顺序：风格与色彩 → 穿搭/妆容/发型方案 → 先看明星 → 再跟博主 → 杂志案例
```

完成标准：

| 内容 | 现状 | 两天目标 |
|---|---|---|
| 明星 | 0 位，只有数据位 | 8 种风格各至少 3 位，每位有来源，并放至少 2 张私服照 |
| 杂志案例 | 6 个，全站共用 | 至少 40 个，每种风格至少 5 个，报告按风格显示 |
| 博主 | 14 位，古典型和戏剧型各 1 位，其余各 2 位 | 每种风格至少 3 位，新增的都要取得授权 |
| 拍照分析 | 没有 | 上传或拍一张照片，预填能判断的题目，用户可改 |
| 报告内容 | 有穿搭、妆容、发型、衣橱、7 天练习 | 增加饰品、要强化和弱化的点、三个月计划 |

已完成，不用重复做：

- 报告丢失已修复：答案和报告保存在本机浏览器，点“清空本次选择”可删除。
- 三维录入已加入第 2 步（选填），报告会判断梨形、曲线型、H 型、倒三角、O 型并给出版型建议。判断规则待专业复核。
- 发型已细化到刘海、齐刘海、直发或卷发、发色。内容待专业复核。

## 2. 协作方式

- **GitHub 私有仓库是唯一的项目来源。** 代码、数据和文档都以仓库里的版本为准。
- **Codex 是每个人的工具。** 用 Codex 云端或本地版都可以，改完都要提交 Pull Request（PR）。
- **ChatGPT 共享项目（Shared Project）放资料和指令。** 由负责人创建并邀请队友，上传本文和 `AGENTS.md`，大家在同一背景下查资料、起草内容。结果要写进仓库才算完成，因为共享项目不负责合并代码。
- **任务认领用 GitHub Issues。** 每张任务卡（第 4 节）建一个 Issue，指派给负责人。
- **Codex 规则写在 [AGENTS.md](../AGENTS.md)。** Codex 进入仓库时会读取。

流程：

1. 开始前拉取最新 `main`，新建分支 `姓名/任务名`。
2. 只改自己负责的文件，一次 PR 只做一件事。
3. 自己打开网站走一遍，把截图贴到 PR。
4. 负责人检查并合并。每半天至少合并一次，不要攒到最后。

## 3. 分工

如果有人不写代码，优先安排 A 或 D，这两个任务主要是整理内容。

| 人员 | 任务 | 独占文件 |
|---|---|---|
| 负责人（你） | 建仓库、合并 PR、版权决定、用户测试、比赛提交与演示 | `README.md`、`index.html`、`AGENTS.md` |
| 队友 A | 明星库 | `celebrity-data.js` |
| 队友 B | 杂志案例库 | `app.js`、新建 `case-data.js`、`杂志官网案例*` |
| 队友 C | 拍照分析 | 新建 `photo-analysis.js`、`models/` |
| 队友 D | 博主扩充、拼多多与小红书资料、报告新模块 | `gallery-data.js`、`images/gallery/`、`style-test.js`、`docs/资料笔记/` |

`style.css` 是共用文件：只在末尾追加，并用模块名开头（如 `.photo-*`）。要改别人的文件，先在对方的 Issue 里说一声。

## 4. 任务卡

### A 明星库

- 把每种风格的明星写入 `celebrity-data.js`，字段说明在该文件开头。每种风格的第一位就是报告优先推荐的人。
- 归类依据先看 `小红书形象设计资料.md` 第 1 条（夏允对照表）以及第 175、192 行提到的笔记。原帖要登录查看，由人工打开后录入。
- 每位至少找 2 张私服照，写入 `looks`，`type` 填“私服”并排在最前面。不要放偷拍或侵犯隐私的照片。
- 图片优先用 Wikimedia Commons 等写明授权的来源，并标署名。私服照的合规来源较少；找不到时 `looks` 留空，先放文字和原文链接，并把缺口列给负责人决定。
- `why` 只谈造型，不评价长相、不谈性格。
- **验收：** 8 种风格各测一次，报告里明星都排在博主前面，来源链接能打开。

### B 杂志案例库

- 先把 `app.js` 里的 `S` 和 `cases` 移到新文件 `case-data.js`，一条案例一行或多行展开，避免合并冲突。第一个 PR 只做这件事。
- 给每条案例增加 `styles: ['natural', ...]`，再扩充到至少 40 条。沿用现有字段，事实、解读、日常借用分开写。
- 把真实案例区改成可按风格筛选；报告按 `styles` 自动选案例，代替 `style-test.js` 里写死的 `cases`（这一处与 D 协调）。
- 每条都要有来源、年代、署名；未知字段留空，不要编。
- **验收：** 8 种风格的报告都至少显示 3 个不同案例，图片打不开时原文链接仍可用。

### C 拍照分析

建议方案：用 MediaPipe Face Landmarker 在浏览器本地取 478 个面部关键点，照片不上传，不需要 API Key。这里只测量五官比例，不识别这个人是谁。

**先验证再投入：** 第一天中午前用几张照片跑通“照片 → 关键点 → 预填一道题”。跑不通就停止，改去帮 A 或 B，网站继续用手动答题。

- 在 `index.html` 已预留的 `<div id="photo-analysis"></div>` 里放上传入口（`<input type="file" accept="image/*" capture="user">`）。
- 把结果换算成题目答案，调用 `window.applyTestAnswers({题目id: 选项值})` 预填。题目和选项值见 `style-test.js` 的 `QUESTIONS`。
- 第一版只预填几何特征能判断的题：`face`、`features`、`eye`、`jaw`、`browShape`、`lip`、`faceShape`。
- 身高、骨架、身体线条、表情和朋友评价仍由用户回答。色彩题受光线影响大，只作低可信度提示。判断不准时选“不确定”，不要硬选。
- 模型和 wasm 文件放进仓库，不依赖外网。上线前到 MediaPipe 官方仓库和模型页确认许可证。
- 界面必须说明：照片不上传、结果可修改、不是科学诊断。未成年用户也可能使用，因此不保存照片。
- 阈值要校准：至少找 20 张经本人同意的照片，和本人手动答案对比，并把一致率写进 PR。
- **保底：** 第一天结束时还没有跑通，就只展示手动答题，不影响提交。
- **验收：** 同一人换 3 张正面照，结果基本一致；没有人脸或多张人脸时有明确提示；关闭网络仍可分析。

### D 博主、资料与报告内容

- 优先补古典型和戏剧型，每种风格至少 3 位博主。每位都要取得授权后才能放图，并记录授权时间。
- 整理小红书和拼多多的形象设计资料，笔记放到 `docs/资料笔记/`：只学习结构和方法，用自己的话重写，注明来源。原件放本地 `private/`，这个文件夹不会上传。
- 给 `style-test.js` 的 `STYLES` 增加饰品、强化与弱化重点、三个月计划，并显示在报告里。新增内容要标注“待专业复核”。
- 把 `gallery.js` 和报告里写死的“她”改为中性称呼。
- **验收：** 8 种风格的报告都显示新模块，内容不是互相复制；“不化妆”和“预算 0 元”仍然有效。

## 5. 两天节奏

| 时间 | 负责人 | 队友 |
|---|---|---|
| 开工前（约 1 小时） | 建私有仓库，建 Issue，邀请队友 | 确认能打开仓库、能用 Codex |
| 第一天上午 | 开 15 分钟会，确认本文 | B 完成数据拆分；A 和 D 定名单；C 跑通关键点识别 |
| 第一天下午 | 合并 PR，检查方向 | A 完成每种风格 1 位；B 到 20 条；C 预填跑通；D 补博主 |
| 第一天晚上 | **决定拍照功能是否保留** | 全部提交当天进度 |
| 第二天上午 | 只合并已完成的内容 | A、B、D 补足数量；C 校准阈值 |
| 第二天中午 | 找 3–5 位目标用户试用并记录问题 | 停止加新功能 |
| 第二天下午 | 录演示、准备提交 | 只修问题：手机端、坏链接、错别字 |

## 6. 不能碰的红线

- `_raw/` 含登录状态下保存的小红书页面，只留在本地，不能上传。
- 不提交密钥、账号或 Cookie。
- 不提交付费课程、拼多多资料的原件或大段原文。
- 不写没有来源的明星归类和杂志信息，不用 AI 生成人物图。
- 风格只描述穿搭语言，不判断性格、能力或人的价值。
- 演示前由负责人确认：比赛是否允许使用明星和杂志图片。这批图片目前只是研究参考，没有商业授权。
