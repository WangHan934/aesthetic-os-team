# Aesthetic OS 两天协作方案

修订日期：2026-11-07（第 2 版）。比赛的提交时间和评分标准还没有写入本文，请负责人补上。

## 1. 这次改了什么

老师的新要求：**重点做可视化，把平面页面升级成三维，比如捏脸；尽快加上拍照识别五官；发型、妆容、身材都要有图片。**

产品流程改为：

```
拍照识别或手动答题 → 用户确认 → 3D 捏脸（脸型、身材、发型、妆容、服装实时变化）→ 风格报告
报告顺序：风格与色彩 → 图文方案 → 先看明星 → 再跟博主 → 杂志案例
```

优先级：

1. **必须有：** 能转动的 3D 人台、拍照预填、发型/妆容/身材图库、8 种风格的明星。
2. **应该有：** 杂志案例扩充、博主补齐。
3. **时间够再做：** 饰品、三个月计划等报告文字模块。

3D 人台只是示意效果，不是本人的真实复刻，也不是虚拟试衣。

## 2. 协作方式

- **GitHub 仓库是唯一的项目来源。** 任务内容以 [Issues](https://github.com/sylviadwilson33-coder/aesthetic-os-team/issues) 为准。
- **ChatGPT 共享项目放资料和指令。** 内容要写进仓库才算完成。
- **Codex 规则写在 [AGENTS.md](../AGENTS.md)。**

流程：

1. 开始前拉取最新 `main`，新建分支 `姓名/任务名`。
2. 只改自己负责的文件，一次 PR 只做一件事。
3. 自己打开网站走一遍，把截图贴到 PR。
4. 负责人检查并合并。每半天至少合并一次。

**#5 推送前，队友 C 不要开始写 3D 和拍照代码。** 这部分正在负责人的 Claude 会话里做，否则会重复。其他人可以先开工。

## 3. 分工

| 人员 | 任务 | Issue | 独占范围 |
|---|---|---|---|
| 负责人（你） | 3D 与拍照的基础版、合并 PR、版权决定、用户测试、提交与演示 | #5 | `index.html`、`README.md`、`AGENTS.md`，以及 #5 新增的 3D 和拍照文件（推送前） |
| 队友 A | 明星库 + 私服照片墙 | #1 | `celebrity-data.js` |
| 队友 B | 杂志案例库 + 可视化案例墙 | #2 | `app.js`、新建 `case-data.js`、`杂志官网案例*` |
| 队友 C | 接手 3D 和拍照：校准、补发型服装、手机端 | #3 | #5 推送后，接手 3D 和拍照相关文件 |
| 队友 D | 发型、妆容、身材图库 + 博主补齐 | #4 | 新建 `visual-data.js`、`images/visual/`、`gallery-data.js`、`images/gallery/`、`docs/资料笔记/` |

如果有人不写代码，优先安排 A 或 D。`style.css` 是共用文件：只在末尾追加，并用模块名开头（如 `.studio-*`）。要改别人的文件，先在对方的 Issue 里说一声。

## 4. 两天节奏

| 时间 | 负责人 | 队友 |
|---|---|---|
| 第一天上午 | 邀请队友，开 15 分钟会，确认本文 | A、B、D 开工；C 准备校准照片和测试手机 |
| 第一天下午 | **推送 #5 基础版** | A 每种风格 1 位；B 拆分数据并到 20 条；C 接手；D 完成发型图 |
| 第一天晚上 | **决定 3D 和拍照的最终范围** | 全部提交当天进度 |
| 第二天上午 | 只合并已完成的内容 | 全员补足数量；C 完成校准 |
| 第二天中午 | 找 3–5 位目标用户试用并记录问题 | 停止加新功能 |
| 第二天下午 | 录演示、准备提交 | 只修问题：手机端、坏链接、错别字 |

**保底：** 3D 不稳定时，演示时改用静态图库和手动答题，不影响提交。

## 5. 不能碰的红线

仓库现在是**公开**的，提交的内容所有人都能下载。

- 新抓取的小红书图片，取得作者授权前只放本地 `private/`，不能提交。
- 身材照片只用成年人的穿搭照，并取得本人或作者授权；不放儿童、不放偷拍。
- 用来校准的真人照片和三维数据绝不提交。
- `_raw/`、付费资料原件、密钥、账号、Cookie 都不提交。
- 不写没有来源的明星归类和杂志信息，不用 AI 生成人物图。
- 风格和身材只用来选穿搭，不判断性格、能力或人的价值。
- 演示前由负责人确认：比赛是否允许使用明星和杂志图片。
